## Control-by-control observations

All controls named below were in the Tab order shown. Each standard element or date segment had an on-screen 2 px solid outline when focused. Each native **Show date picker** button showed a separate blue focus ring in the browser screenshot. For text fields, numeric fields and date segments, ordinary text, digits or arrow keys are the relevant interactions. Fields whose values were left at their defaults are identified below.

- **Today.** After activating the Today link, Tab ×8 traversed the other seven shell controls and reached **Complete keyboard plan**. Tab ×2 checked the boundary and returned to Today. Shift+Tab ×2 returned to the completion control. Enter submitted one completion (HTTP 200). The completion awarded 10 quest XP plus a 25 XP recovery seal. There was no second primary button on the seeded Today state.
- **Quests, catalog.** From the Quests link, Tab ×10 reached **New quest** through the six remaining shell stops and **Category filter**, **Recurrence filter**, **Status filter**. Each filter accepted Space → Down → Enter and changed from All to Academic, Daily and Active respectively. Enter opened **New quest**. In the populated catalog, **Edit keyboard plan** followed New quest with the editor closed. Enter opened the editor. Shift+Tab reached **Cancel**, and Space closed it. **Save changes** was focusable immediately before Cancel in Edit and was not activated.
- **Quests, Create form.** After New quest, the order was **Title → Category → Difficulty → Target → Quest recurrence → Effective date** (day, month, year, **Show date picker**) **→ Create quest → Cancel**. From Title, the literal keys for “keyboard plan”, Tab ×9 and Enter on Create quest saved the quest (HTTP 201). Category and Difficulty opened with Space and closed with Enter. Target was left at 1. Space → Down → Enter on Quest recurrence selected Weekly in a separate open editor. After the date picker, the optional **Monday, Tuesday, Wednesday, Thursday, Friday, Saturday and Sunday** checkboxes were each reached with Tab and toggled with Space. Space on the date picker opened its calendar and Enter selected a date. Tab to Create quest, then Cancel, followed by Space cancelled that optional branch.
- **Habits.** From the Habits link, Tab ×6 reached the first **Week starting** date segment. Tab reached its month segment, Up updated the grid, and Tab ×2 reached its year segment and **Show date picker**. Space opened the native calendar and Enter selected a date. The input and rendered grid changed together. The grid had no further interactive controls.
- **Progress.** From the Progress link, Tab ×5 reached **Load more entries**, passing Profile, Settings, Onboarding and Sign out. A read-only browser DOM check counted the children of the “Progress ledger” list before activation (25) and after the response rendered (34). Enter therefore loaded a second page of 9 rows. The button disappeared once the ledger was exhausted. The static heatmap, seals and ledger rows presented no additional tab stops.
- **Profile.** From the Profile link, Tab moved to **Settings → Onboarding → Sign out**, then out of the page controls, then back to Today. The successful page exposed no Retry button.
- **Settings.** From the Settings link, Tab ×3 reached **Display name** through Onboarding and Sign out. The remaining form order was **Timezone → Add goal → Save settings** when the form was dirty. Timezone stayed UTC. On Add goal, Enter inserted **Goal 1** and **Remove goal 1** between Timezone and Add goal. Shift+Tab ×2 reached Goal 1 via the remove button. After typing “read”, Tab and Space removed it. For the save, **Display name → Right ×25 → literal keys for “ reviewed” → Tab ×3 → Enter** reached Save settings and saved the change (HTTP 200). An earlier attempt to go backward from the wrapped Today link reached the page body instead of Save. That Enter did not submit. The forward sequence reached and activated Save on the next visit.
- **Onboarding.** From the Onboarding link, Tab passed **Sign out → Display name → Timezone → Add goal → Quest title → Category → Start date** (day, month, year, **Show date picker**) **→ Save settings and create quest**. Name and timezone used the prefilled values. Space on Add goal inserted **Goal 1** and **Remove goal 1** before Add goal. Shift+Tab ×2 reached Goal 1, the keys for “read” entered a goal, and Tab → Enter removed it. From the Onboarding link, Tab ×5 reached Quest title, where “keyboard starter” was typed. Tab ×2 reached the date. Typing `24`, `11`, and `2026` completed the date using the browser's automatic segment advance. Tab reached the picker icon and Tab again reached the submit button. After checking its forward boundary, the form was traversed again to the same submit button and Enter saved settings (HTTP 200) and created the quest (HTTP 201). A separate pass used Space to open Category and the native date picker and Enter to close or select.
- **Sign out.** After the final Onboarding traversal, Tab returned to Today. Tab ×7 then reached **Sign out**. Enter issued a logout POST (HTTP 200) and took the tab to `/login`. An earlier focus-counting slip pressed Space while Sign out was focused, which also signed out successfully. The fixture account was signed back in with the keyboard (HTTP 200) and the intended route checks continued.

The optional Profile retry, error-only controls and Quests pagination were not present on the tested states. The empty Today “Browse quests” link was visible before the fixture was prepared and was not activated. Native popup internals were exercised for opening and selection, with the page-level Tab audit conducted after those popups closed.
